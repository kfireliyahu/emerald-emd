Finding entries

Today an entry is reached only through its format's table (or a board, a roadmap, a name under Links here), and the palette finds formats by name but no entry at all. This mockup draws the three pieces you asked for, in one window, on a made-up notebook of ten formats and 1,822 entries: (1) formats as folders in the rail, each opening to its entries by their title; (2) a list to page through beside the one entry view, searchable, moved with the arrow keys, keeping its filter; (3) the whole document searched from the palette, Ctrl+K, landing on the entry. Where the choice is real there are two directions; the one marked pick is the driver's, and the reasons are under the window.

Notes for the build (M37 U2)

  • The folder's entries are a query, not the whole table. listRows with the format's default order (the first text column, or the order a view sets) and LIMIT 12; the filter line is the same search the Table's band sends, so 37 matches in the rail are the 37 its All 37 opens. The entry open is always shown in its folder, appended if it is past the twelve, so the rail always marks where you are.
  • Which folders are open is the viewer's, not the document's: kept the way the rail's collapsed state is (useSidebar), per window. The format you are in opens by itself, as a section does today. This amends the rail's no disclosure triangle rule (Sidebar.tsx's comment, D-130) for formats only; the sections keep it.
  • The list is the pager made visible. It reads the rows the entry's pager already walks: the address's filter and search (M44 U7), in the Table's order. Its search box writes ?search=, so a reload, Back and a bookmark keep it, and the Table opened from the entry shows the same rows. ↑ ↓ move whenever no field is being typed in (the M35 entry has no box until a value is pressed), and from the list's own search box.
  • An entry opened from outside the list's search (the palette, Links here, the rail) lets the search go, so the list always holds the entry beside it and its foot never says – of 20.
  • The list draws a row as its title and one line beneath: the entry's header line (D-401's header columns), the first two, with an enum as its dot. Hundreds draw as they are; past a thousand the list windows itself, as the Table does.
  • Hidden is per viewer, one button in the entry's bar, and a narrow window hides it. A pack's read-only entry (D-269) keeps the list.
  • The palette's entries come after places and commands, so Save is never buried: four per format, a 12 more in Recipe row that opens the list holding the search, and nothing at all under two characters. Ranked: a name that starts with it, a word in the name that does, a name that holds it, then any other column, by searchDocument's column hits; Hebrew through Bidi.
  • Parity holds without a new tool: the rail's folder is format_rows order limit:12 search, the list is format_rows with the address's filter, and the palette is search_document. U2 writes the test that the palette's hits are search_document's.
  • Probably three sessions, so U2 splits first: the rail's folders, the entry's list, the palette's search; each lands on the one entry view.
